## Akar masalah (urutan dampak)

1. **docs_url salah** — 7 lib resolve dengan trust rendah menunjuk GitHub/homepage, bukan docs resmi: polars (README), tailwindcss (homepage), astro (homepage), duckdb (github), express (github), prisma (github), fastapi (`/reference/dependencies` halaman tunggal!). Akibatnya crawler meng-ingest halaman yang salah → korpus cacat sejak awal.
2. **Ingest parsial (chunk hilang)** — 13/14 lib yang dipakai hanya punya 1 distinct path di DB (fastapi 1, express 1, prisma 1, polars 1, tailwindcss 1, astro 1; react 10 path tapi tanpa /reference/; duckdb 8 path tapi hanya /clients/). Query topik di luar korpus mustahil hit.
3. **Ranking/retrieval gagal walau chunk ada** — numpy `basics.broadcasting` ada di DB tapi query broadcasting hanya keluar c-info; numpy "random seed" keluar top kosong. Indikasi embedding/retrieval lemah, bukan korpus.
4. **Top-5 duplikat** — fastapi, express, prisma, tailwindcss, polars, requests mengembalikan path yang SAMA 5x → hit@5 = hit@1, kapasitas hasil terbuang, tidak ada diverse candidates.
5. **Latency resolve network lookup** — 1.8–9.2 s untuk lib yang belum ada di registry (vs 0–2 ms yang cached); memperlambat keseluruhan pipeline.
